# Architecture decision log
- 2026-10-28 | D01 | Original IP only; Tarkov inspires loop; BODYCAM inspires camera language. No game assets or exact UI reproduced.
- 2026-10-28 | D02 | Single-place, two-zone prototype (safehouse and instanced logically separated raid) before TeleportService/MemoryStore.
- 2026-10-28 | D03 | Server authority for valuables, combat, raid outcomes and persistence.
- 2026-10-28 | D04 | Performance-first original low-poly art and adaptive bodycam overlay.
- 2026-10-28 | D05 | One stage per Claude Code session; no Cowork and no extra agents.
- 2026-10-28 | D06 | Rojo serve port 34873 (34872 belongs to another local project). Rojo 7.7.1 pinned via Rokit.
- 2026-10-28 | D07 | Meshes are procedural Blender scripts (vertex colour, no textures), uploaded via Open Cloud with a key kept only in the owner's home folder; loaded at runtime with InsertService.
- 2026-10-28 | D08 | Audio: original procedural SFX (assets/audio/synth_sfx.py) plus Roblox-licensed library ambience. Creator Store rips rejected.
- 2026-10-28 | D09 | Studio-only test bridges (ServerStorage.ZR_Dev, PlayerScripts.ZR_ClientDev) drive integration and exploit tests; never created on live servers.
- 2026-10-28 | D10 | Project renamed to Zero Return (formerly Escape From Bloxov); PC folder name unchanged for now.
- 2026-10-28 | D11 | Body version ZR_BLOCK_R15_V1: the owner's block proportions on block-proportioned R15 names, keeping the project's working Motor6D skeleton and shared RigMath procedural animation (server C0 hitbox pose, client Transform). No skinned meshes and no second rig; one rig for players, player scavs and all AI. Limitation: the block head pivots on a block neck, so looking up under a tall pack is capped (NeckUp) and the waist takes the rest.
- 2026-10-28 | D12 | Worn equipment is rigid Blender MeshParts welded to one body segment. They are unanchored, massless and have no collision, queries or touch, so hits use the body parts and protection comes only from Items. Layers are fitted by scaling each torso layer over the shells of the layers worn under it, with separate shoulder-strap lanes, instead of layered-clothing cages.
- 2026-10-28 | D13 | Appearance is derived on the server from the equipment slots plus a look (Equipment.resolve) and diffed per slot by signature. The holder's equipment revision (erev) refuses stale equip requests. Clients never send visual keys, meshes or armour values. Missing meshes get a logged neutral box and are reconciled from the current state when the asset arrives.
- 2026-10-28 | D14 | Clothing and markers are role looks; armour, storage, headwear, headsets and face covers are items. Presets: operator (player kit), scavenger (4 seeded variants), Harbor Watch guard (armband), bodyguard (comms headset + shoulder markers), the Foreman (padded jacket over concealed armour, fleece collar, boot cuffs, hard hat item). Scout and safehouse worker are backlog.
- 2026-10-29 | D15 | Look 2.0 (M12): worn surfaces are MaterialVariants on the server-built map (seen by everyone); clutter and grime are a client-side detail layer built from a seeded server plan (`DetailPlan` -> `ReplicatedStorage.ZR_DetailPlan`, client `Detail`), never colliding, taking bullets or blocking sight; gameplay cover is server geometry. Graphics levels 0 POTATO .. 3 HIGH change presentation only (fog, light and geometry identical). HIGH is the default on every platform, phones included (owner decision); POTATO is opt-in; a one-time hint suggests a lower level after 20 s under 24 fps.
